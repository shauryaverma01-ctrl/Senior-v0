# Maya v6.3 — Escalation Deploy Checklist

Drafted 2026-05-18. Minimal cut: no DB migration, no shared helper, no new
columns. Only an Edge Function + one secret + Zoronal dashboard config.

## What v6.3 ships

When the caller asks for the manager (the welcome message offers this as the
third option), Maya invokes the new `escalate_call` on-call tool. The tool:

1. Reads `MANAGER_ESCALATION_PHONE` env var → redirect target.
2. Fires URGENT Telegram alert to the manager chat with caller number + summary.
3. Returns `{action: "transfer", target_number, say, end_call}` — the directive the voice platform consumes to perform the actual SIP transfer.

Vendor-neutral. Same URL serves Zoronal tonight + Ringg when Aaryak's ready.

Trigger scope for v6.3: **`asked_for_manager` only.** Future iterations may
add `live_order` (Zomato/Swiggy), `loop_fallback` (AI confusion).

## Step 4 — Register the tool on Zoronal dashboard

Log into Zoronal → Maya agent → Tools / On-call tools → Add new tool.

| Field | Value |
|---|---|
| Tool name | `escalate_call` |
| Description | `Invoke when the caller asks for the manager, says "transfer me," "talk to a person," or otherwise wants to speak to a human. Call this ONCE, then read the response's "say" field verbatim as your final line, then end the call. Do not invoke during reservation flow unless caller explicitly escalates.` |
| Method | `POST` |
| URL | `https://xslbbnbsyuklayewuhsc.supabase.co/functions/v1/escalate-call` |
| Headers | `Authorization: Bearer <SUPABASE_ANON_KEY>` + `Content-Type: application/json` |
| Body params Maya fills | `reason` (string, default `asked_for_manager`), `caller_number` (string, optional, E.164), `summary_so_far` (string, optional, one sentence) |

**Critical:** confirm how Zoronal consumes the response's `action: "transfer"` + `target_number` for an actual SIP transfer. Three possibilities — note which applies after the live call test (Step 6):

1. Zoronal recognizes a standard response shape (e.g. `transfer_to`) and bridges automatically.
2. Zoronal needs a separate "transfer phrase" / "transfer destination" config on the agent.
3. Zoronal has no built-in transfer — Maya delivers the `say` line and hangs up; manager calls back from the Telegram alert.

Even worst-case (3), the Telegram path works. The user-visible behavior degrades from "ringing your phone in seconds" to "call back from the alert within minutes" but the feature still delivers.

## Step 5 — Sync v6.3 prompt to Zoronal

Copy v6.3 prompt block from `docs/maya-prompt.md` → paste into Zoronal → Maya → Prompt field → Save. Welcome Message field is unchanged from v6.1/v6.2.

## Step 6 — End-to-end live call test

Call the Zoronal DID from a personal phone (NOT `+919650795900`). When Maya greets, respond with "speak to the manager."

Expected:

1. Maya: "Of course — let me connect you to a staff member."
2. `escalate_call` fires. Supabase logs → `escalate_call` event.
3. URGENT Telegram alert arrives.
4. Maya: "I'm transferring you to a staff member now — please stay on the line."
5. Call attempts redirect to `+919650795900`.
   - If Zoronal supports transfer → your phone rings.
   - If not → call drops; you read the Telegram alert and call back.

Update this checklist's Step 4 with which outcome you got.

## Rollback

If anything misbehaves in production:

1. **Disable the tool on Zoronal** — remove `escalate_call` from Maya's on-call tools list. Maya can no longer invoke it; the prompt's instructions become inert.
2. **Or revert the prompt** — paste v6.2 prompt back into Zoronal.

Nothing to roll back at the DB or function level — both are additive and non-destructive.
