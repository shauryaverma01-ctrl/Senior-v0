Drafted 2026-05-16. Files edited in this Senior repo working tree but

## What v6.2 ships

One new path layered on v6.1: when Maya detects a vendor pitch ("I'm calling
about supplying X"), she switches into capture mode (name, category, offer,
price). End-of-call → row in `vendor_leads` (the table is already created on
the live Supabase project). Manager sees the lead on the dashboard's
`/vendor-leads` screen within seconds via realtime.

**Customer calls unchanged** — Maya keeps handling reservations, FAQs,
returning guests, Hinglish, the works. No transfer_call tool needed. No
staff_inquiry path. Scope is deliberately narrow per Shaurya's call.

## Risk surface (read before deploying)

- **Welcome message stays v6.1.** Vendors don't get explicitly invited.
  Detection happens mid-conversation when they self-identify. If you find
  vendors falling through to reservation flow (Maya asks "how many people?"
  to a vendor), the fix is either a tighter VENDOR DETECTION regex or
  adding "or supplier business" to the welcome message.
- **`source` is free-text in `vendor_leads`.** The dashboard's filter chips
  show whatever statuses exist; typos make new chips. Manager can clean up
  manually.
- **Ringg lag.** Ringg-side vendor calls won't capture until Aaryak deploys
  the same one-branch patch to `ringg-webhook/index.ts`. Until then, those
  calls land in the `incomplete` path (logged to Telegram, no vendor_leads
  row). Acceptable for v0.
- **Maya might over-classify.** A customer saying "I'd like to order a
  birthday cake supply for 20 people" could trip the vendor regex. If you
  see false positives in `vendor_leads`, tighten VENDOR DETECTION cues.
