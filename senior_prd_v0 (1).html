1. Product Overview

Senior is an inbound voice AI concierge for restaurants in India. Maya, Senior's AI agent, picks up 100% of inbound calls, captures reservations, answers FAQs, and routes complex requests to the manager — all in under 2.5 seconds on Indian PSTN. Built on Zoronal's voice infrastructure with a Supabase data layer and Telegram ops loop, Senior deploys for a new restaurant in 5 days with zero telephony engineering.

Senior is built on three architectural principles: Zoronal handles the voice plane; Supabase owns all data (portable, vendor-neutral); everything between them is a single Edge Function. Swapping voice vendors is a 2-week project, not a rebuild.

The Direct Booking Flywheel

Maya actively offers callers a 15% weekday dinner discount for booking via this line instead of District or EazyDiner. The customer saves money. The restaurant saves the 10–20% aggregator commission. Senior pays for itself from the first direct booking it captures.

One-Line Pitch

Never miss another reservation call — Senior picks up every call, captures every booking, and costs less per month than 4 hours of front-desk staff time.

2. Problem Statement

A Delhi cafe misses 30–60 inbound calls a month during peak hours. Staff are serving tables. The phone rings out. The customer books on Zomato or District — paying a 10–20% aggregator commission that cuts directly into the restaurant's margin. For a 250–300 call/month restaurant with a 20% miss rate, that is 50–60 missed booking conversations — roughly ₹25,000–35,000 in recoverable reservation revenue walking out the door every month.

9. System Architecture

Senior is a real-time voice pipeline with a thin ops layer. The architecture has three planes:

  • Call Plane: Customer PSTN → Plivo DID → Zoronal (STT + LLM + TTS + agent logic) → check_capacity tool → call end
  • Data Plane: Zoronal webhook → Supabase Edge Function → Postgres (Supabase) ↔ Supabase Studio (owner/manager view)
  • Ops Plane: Telegram Bot (manager notifications + Confirm/Decline) + Zoronal dashboard (call history + recordings) + Supabase Studio (reservation table)
Vendor Portability Rule — Non-Negotiable

Every webhook payload, every transcript reference, every reservation is mirrored to Supabase at the moment Zoronal fires. The Zoronal → Supabase Edge Function boundary is the ONLY point of vendor contact. Replacing Zoronal with Pipecat or any other voice vendor requires rewriting only the Edge Function that receives the webhook. The database layer, the ops layer, the manager flow — all portable. This rule is enforced from Day 1.

9.6 Supabase Schema (Run as SQL in Supabase Editor)

-- restaurants
create table restaurants (
  id           uuid primary key default gen_random_uuid(),
  name         text not null,
  short_name   text,
  zoronal_agent_id text,
  plivo_did    text,
  telegram_chat_id text,
  created_at   timestamptz default now()
);

-- knowledge_cards
create table knowledge_cards (
  id            uuid primary key default gen_random_uuid(),
  restaurant_id uuid references restaurants(id),
  json_content  jsonb not null,
  version       int default 1,
  updated_at    timestamptz default now(),
  updated_by    text
);

-- capacity_caps
create table capacity_caps (
  id            uuid primary key default gen_random_uuid(),
  restaurant_id uuid references restaurants(id),
  day_of_week   text,   -- monday|tuesday|...|saturday|sunday|default
  slot_start    time,
  slot_end      time,
  max_bookings  int
);

-- calls
create table calls (
  id              text primary key,   -- Zoronal call_id
  restaurant_id   uuid references restaurants(id),
  caller_number   text,
  started_at      timestamptz,
  ended_at        timestamptz,
  duration_seconds int,
  intent          text,   -- reservation|faq|escalation|incomplete
  status          text,   -- completed|dropped|failed
  summary         text,
  transcript_url  text,
  audio_url       text,
  created_at      timestamptz default now()
);

-- reservations
create table reservations (
  id                uuid primary key default gen_random_uuid(),
  call_id           text references calls(id),
  restaurant_id     uuid references restaurants(id),
  customer_name     text,
